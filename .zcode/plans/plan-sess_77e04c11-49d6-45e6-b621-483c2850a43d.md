# 双链生态实施计划(wikilink 全家桶)

**决策基线**:语法完整三件套(`[[目标]]` / `[[目标|别名]]` / `[[目标#标题]]`);改名自动重写引用(Obsidian 式);图谱引入 d3-force(懒加载独立 chunk,仿 pinyin-pro 模式)。反链索引采用**按需扫描**(复用 search.cjs 扫描范式,不做常驻增量索引)。共 8 个阶段,每阶段独立 commit;全部完成后正式翻案路线图「明确不做」记录。

## Phase 1 语法内核 `src/wikilink.ts`(新建)

完全照 mark-ext.ts 五段式:
1. **mdast transform 纯函数**:text 节点内切分 `\[\[([^\[\]\n]+?)\]\]` → `{type:'wikilink', data:{target, alias?, heading?}}`;先按第一个 `|` 切别名、再按第一个 `#` 切标题;行内代码是原子节点天然免疫,另套反引号/公式守卫(仿 `inUnclosedSpan`);
2. **$remark attacher**:parse transform + `toMarkdownExtensions` handler 无损输出(往返 byte-perfect);
3. **$nodeSchema 行内原子节点**:`atom/inline`,attrs `{target, alias, heading}`;toDOM 渲染 `<a class="wikilink">别名||目标</a>`,parseDOM 接粘贴;NodeView 按 resolver 结果切 unresolved 样式(虚线/暗色);
4. **$inputRule**:`/\[\[([^\[\]\n]+)\]\]$/` + 守卫(仿 footnote_reference 的 replaceWith);
5. **点击跳转**:$prose handleClick 命中 wikilink 节点 → 调注入的 follow 回调(仿 link-nav 的 setLinkNavContext 注入模式)。
接入:editor-core.ts 在 `.use(gfm)` 之后 `.use(wikilinkPlugins)`。单测:切分边界/往返恒等/输入规则/attrs 序列化。

现状是纯 CommonMark 高亮。新增 @lezer/markdown InlineParser 识别 `[[...]]`,以 `cmMarkdown({ extensions })` 传入,`sourceHighlightStyle` 加条目(accent 色)。只加 wikilink,不动 base,避免影响现有高亮行为。

## Phase 3 索引与解析 `electron/wikilinks.cjs`(新建)+ `src/wikilink-index.ts`(新建)

- 纯 Node 模块(仿 search.cjs,可脱壳单测):`scanWikiLinks(roots)` 枚举 .md(沿用 SEARCH_SKIP_DIRS/5000 文件上限/truncated 标记),逐文件行级解析 wikilink(**跳过 ``` 围栏块**的行状态机),一次扫描返回 `{ notes[], edges[{source, targets[]}], truncated }`——反链面板与图谱共用同一数据;
- `resolveTarget`:①相对路径精确匹配 → ②同目录同名 → ③全工作区唯一文件名 → ④多匹配返回 ambiguous 交 UI;
- IPC `tmd:wiki-scan` + preload + native.ts 桥接;
- 渲染层索引缓存 + 失效信号(保存/改名/文件夹树变化),`setWikilinkContext` 注入编辑器;
- 跳转:resolve → `openPath` → 标题锚在打开后于实时文档内按标题文本定位滚动(仿 search.ts locateMatch 的 occurrence 机制);未解析点击 → toast 提示(v1 不自动建笔记)。

## Phase 4 反向链接面板 `src/backlinks.ts` + `src/templates/backlinks.html`

复用 search-overlay/search-panel 外壳(仿 history.html 的修饰类做法);按来源文件分组列出引用当前笔记的 `[[...]]` 及所在行文本,点击 → openPath + 定位该处(复用 findTextRanges);打开时扫描 + 保存时防抖刷新;Esc/遮罩关闭并入 main.ts 统一收口,15-print.css 隐藏;入口:⋯ 菜单 + 命令面板 + SHORTCUT_DEFS 新项(默认 Cmd/Ctrl+Shift+B);i18n `backlinks.*` 三份语言包。

## Phase 5 改名自动重写 `src/link-rewrite.ts`(新建)

单点接入 `files.ts renameEntry` 成功后:取 edges(缓存过期重扫)→ 找出引用旧名的 source → 逐文件处理:已打开标签 → **tab.markdown 文本级重写**(同款围栏跳过状态机;干净标签同步 native.saveFile——自动获得 noteWrite 指纹豁免不触发重载提示;脏标签只改内存待保存),未打开文件 → readFile + 重写 + saveFile(不在监视集合,无感,顺带进历史快照);toast 汇总「已更新 N 个文件」。只做文件改名(应用无文件夹移动);删除文件不重写(悬挂链接由 unresolved 样式 + 反链面板自然呈现)。

## Phase 6 导出适配 `src/export-doc.ts` / `export-latex.ts`

`createExportMarkdownIt()` 注册 `tmd_wikilink` inline 规则(ruler.before('text'),仿公式保护 mathRule)→ 渲染规则:**所有载体统一降级为带 wikilink 样式的 span 文本**(别名||目标),不产出死链——与 LaTeX「相对链接退化纯文本」既有先例一致;LaTeX 同样降级纯文本。export-doc/export-html/export-latex 各补单测。

## 风险与既定边界

- 序列化 byte-perfect 是硬要求(toMarkdown handler 照 mark-ext 的 wrapHandler 模式);target 内含 `|`/`#` 字面量的文件名不做转义,记为已知边界;
- 分屏只读侧同样渲染 wikilink(NodeView 与侧无关),只读侧点击跳转同样生效;
- 已知兼容性事实:`[[...]]` 在 Typora 等其他编辑器里显示为原始文本,这是双链的固有代价(与 Obsidian 互操作没问题);
- 扫描上限沿用 5000 文件/truncated 机制,超限面板顶部提示。
