# TMD 路线图

> 版本：1.7　作者：chiangyang　更新：2026-09-16
> 本文档的作用：基于 v1.0 现状与主流 Markdown 编辑器（Typora / Obsidian / MarkText）的差距分析，确定后续版本范围，防止开发范围膨胀。每个功能必须归入某个版本或"不做"。
> 相关文档：[需求说明](需求说明.md)　[架构设计](架构设计.md)　[详细设计](详细设计.md)　[打包发布](打包发布.md)

## 1. 现状基线（v1.0 已完成）

核心写作链路已闭环：打开 → 编辑 → 保存 → 导出全流程可用。

- 所见即所得（Milkdown / ProseMirror + GFM）+ CodeMirror 6 源码模式
- Mermaid 实时渲染（自研插件：防抖 / 序号守卫 / 错误兜底 / 主题原地重渲）
- KaTeX 公式、代码高亮、多标签页、查找替换、大纲面板、TOC 块
- 文件树 / 最近列表、粘贴图片双策略（inline / assets 落盘）、相对路径图片解析
- 导出 HTML / PDF、自动保存、崩溃恢复、深浅主题、中英繁三语
- Electron 壳：自绘标题栏、文件关联、单实例锁、CSP 安全、Gitee/GitHub 双源自动更新
- 主题预设（简约白 / 深色 / 羊皮纸 / 护眼绿）+ 设置面板自定义 CSS 注入；设置弹窗吸顶标题栏

## 2. 与主流产品的对比结论

### 2.1 已追平

| 能力 | TMD | Typora |
|---|---|---|
| 所见即所得 + 源码模式 | ✅ | ✅ |
| Mermaid / KaTeX / 代码高亮 | ✅ | ✅ |
| 多标签页 / 大纲 / TOC / 文件树 | ✅ | ✅ |
| 深浅主题 / 中英繁三语 | ✅ | ✅ |
| 崩溃恢复 / 自动保存 | ✅ | ✅ |
| 免费开源 | ✅ | ❌（付费） |

### 2.2 差距（按对日常使用的影响排序）

| # | 差距 | 竞品表现 | 影响 |
|---|---|---|---|
| 1 | 表格编辑弱：无工具栏、不能拖拽调列宽/增删行列 | Typora 有完整表格工具栏 | 复杂表格基本不可维护 |
| 2 | 图片不能缩放/对齐 | Typora 支持拖拽缩放、按比例对齐 | 图文混排受限 |
| 3 | 无 HTML 粘贴转换 | Typora 从网页复制自动转 Markdown | 资料整理场景格式全丢 |
| 4 | 无拖拽打开文件（渲染层未监听 dragover/drop） | 全部竞品支持 | 与系统习惯不符 |
| 5 | 无快速切换面板（Ctrl+P 模糊搜索文件） | Typora / VS Code / Obsidian 均有 | 大项目只能逐级点文件树 |
| 6 | 无跨文件全文搜索 | Obsidian / VS Code 有 | 多文件知识库不可用 |
| 7 | 无多窗口（单实例锁，二次打开转交现有窗口） | Typora 支持多窗口 | **已决策不做**（见「明确不做」）：多标签页已覆盖多文件切换，对照场景走系统级窗口并排 |
| 8 | 语法覆盖不全：无脚注 `[^1]`、高亮 `==mark==`、上下标、YAML front matter | Typora / Obsidian 支持 | 与主流文档兼容性差 |
| 9 | 无分屏预览（源码 + 预览并排） | MarkText 支持 | 部分用户偏好分屏 |
| 10 | 无专注模式 / 打字机模式 | Typora 支持 | 长文写作体验 |
| 11 | 导出格式少：~~缺 Word / 长图~~（v1.3 已补），仍缺 LaTeX | Typora 支持多格式 | 分享场景受限（Word / 图片已覆盖主流需求） |
| 12 | 无主题系统（用户自定义 CSS） | Typora 有大量社区主题 | 个性化受限 |
| 13 | 无历史版本 / 文件快照 | Obsidian 有文件恢复 | 误删无法找回 |
| 14 | 右键上下文菜单缺失：渲染层无 contextmenu 处理，复制/粘贴/剪切无鼠标入口 | Typora/Obsidian 有完整右键菜单（含格式化项） | Windows 用户核心习惯 |
| 15 | 格式化快捷键大面积缺失：仅绑定查找/源码/新建/关标签 4 个键，Ctrl+1~6 标题、Ctrl+K 链接、Ctrl+Shift+K 代码块、Ctrl+Q 引用等全无，主菜单也无"格式/段落"栏 | Typora 全套快捷键 + 段落菜单 | 写作效率硬伤 |
| 16 | 链接点击无响应：无 openExternal IPC 通道，外部链接无法跳转浏览器，无 Ctrl+点击惯例 | Typora Ctrl+点击跳浏览器；相对路径跳本地文件 | 文档引用链路断裂 |
| 17 | 排版设置缺失：无字体 / 字号 / 行距 / 编辑区宽度 / 自动换行开关 | Typora 可自定义字体与行距 | 个性化基础项 |
| 18 | 最近打开只进侧边栏：主菜单无"打开最近"子项，未注册系统跳转列表（addRecentDocument / Jump List） | 竞品均接入系统最近文档 | 系统集成度低 |
| 19 | 导出不跟随主题：导出样式写死浅色，深色模式导出的 HTML 仍是浅色；PDF 无页边距/页眉页脚配置 | Typora 导出可选主题与页面参数 | 导出一致性 |
| 20 | 大文档性能未兜底：MB 级文档 + 数十个 Mermaid 图无虚拟化/懒渲染 | Typora 做过大文档优化 | 极端场景卡顿 |
| 21 | 可靠性设施薄弱：未配 crashReporter 崩溃收集，无 E2E 测试 | 主流编辑器通常接入崩溃收集 | 长期维护质量 |
| 22 | ~~繁中语言包缺失：zh-Hant 暂回退简中~~ | Typora 支持多语言 | 已补齐 zh-Hant（v1.3） |

## 3. 版本规划

### v1.1 —— 编辑体验补课（高优先级）

投入产出比最高的七项，目标：日常写作不输 Typora 基础盘。

- [x] **表格编辑工具栏**：悬浮工具栏（行列增删、对齐）+ 列宽拖拽调整
  - 实现提示：基于 ProseMirror 表格插件（prosemirror-tables）或自研节点视图，列宽存入节点 attrs（已实现：src/table-toolbar.ts——命令直接复用 @milkdown/prose/tables；列宽拖拽由 gfm 预设内置 columnResizing 提供，本无需自研；空单元格 `<br />` 占位与单元格内 `|` 漏转义两个序列化问题均已修复，见 src/table-markdown.ts 与 src/text-escaping.ts）
- [x] **快速切换面板**：Ctrl+P 模糊搜索已打开标签 / 文件树 / 最近列表
  - 实现提示：复用 filetree 读取的目录数据，前端模糊匹配（如 fzf 式子序列评分），无需主进程改动（已实现：src/quick-switch.ts，fzf 式子序列评分纯函数；Ctrl+P 从「打印 / 导出 PDF」接管——高频优先，PDF 改 Shift+Mod+P；拼音首字母匹配暂不支持，见详细设计）
- [x] **拖拽打开文件**：拖 .md 文件进窗口即打开（新标签）；拖图片进文档按粘贴策略插入
  - 实现提示：渲染层监听 drop + dataTransfer.files；Electron 需在主进程 preventDefault navigate（已实现：window 捕获阶段拦截携带文件的拖放；Electron 32+ 路径经 preload `webUtils.getPathForFile` 解析，主进程 `will-navigate` 兜底）
- [x] **HTML 粘贴转换**：剪贴板 text/html 转 Markdown 后插入
  - 实现提示：Milkdown 生态有 html 转 ProseMirror 文档的路径（DOMParser + schema parse），白名单过滤（已实现：src/paste-html.ts——DOMParser 清洗后走 schema 的 parseDOM 规则 parseSlice，转换器零自研；链接/图片协议白名单，降级链图片→HTML→纯文本）
- [x] **右键上下文菜单**：编辑区右键弹出（剪切/复制/粘贴 + 选中文本时的格式化项）
  - 实现提示：自绘 HTML 菜单（复用 ⋯ 溢出菜单样式与交互）或 Electron `Menu.popup()`；按选区与光标上下文动态显隐（已实现：自绘 HTML 菜单 src/context-menu.ts，格式化项复用 format.ts 命令层；粘贴走 execCommand 真实 paste 事件全保真，浏览器模式降级剪贴板 API 纯文本）
- [x] **格式化快捷键与格式菜单**：Ctrl+1~6 标题、Ctrl+B/I、Ctrl+K 链接、Ctrl+Shift+K 代码块、Ctrl+Q 引用、有序/无序列表；主菜单补「格式」栏
  - 实现提示：ProseMirror keymap 绑定 schema 命令（setBlockType / wrapIn / toggleMark）；菜单 accelerator 走 IPC 与渲染层命令统一分发，注意与 CodeMirror 源码模式互斥（已实现：统一命令层 src/format.ts，菜单与编辑器 keymap 双路径；macOS Cmd+Q 为退出应用，引用用 Ctrl+Q；Markdown 无下划线语法，Ctrl+U 不提供）
- [x] **链接点击跳转**：Ctrl+点击外部链接跳浏览器；相对路径链接跳本地文件
  - 实现提示：主进程新增 open-external IPC → `shell.openExternal`（仅放行 http/https）；渲染层 `handleDOMEvents` 或 handleClick 判定 mod+click；本地路径用 `shell.openPath`（已实现：src/link-nav.ts，相对路径按当前文档目录解析，悬停 Mod 键显示 pointer 提示）
- [x] **快捷键自定义**：设置面板可改键，主进程菜单与编辑器同步生效
  - 实现提示（已实现：src/shortcuts.ts 为单一数据源）——29 项快捷键（文件 / 导出 / 格式 / 编辑器四组）集中定义于 `SHORTCUT_DEFS`，配置以渲染层 localStorage 为权威，经 `tmd:sync-shortcuts` 单向同步给主进程重建菜单 accelerator。ProseMirror 端由静态 `keymap({...})` 改为自定义 Plugin 的 `handleKeyDown` 实时匹配配置——静态注册在改键后旧键仍会生效，动态匹配则改键即时生效且无需重建编辑器。设置面板提供按键捕获（capture 阶段拦截）、合法性校验（必须含 Ctrl/Cmd 或 Alt，仅 Shift 会与大写输入冲突）、冲突检测（拒绝写入并在行内就地提示）、一键恢复默认。显示按平台惯例格式化：Windows 加号连接（Ctrl+Shift+O），macOS 按苹果 HIG 的 ⌃⌥⇧⌘ 顺序（⇧⌘O，与系统菜单栏一致）。单测 31 例（shortcuts.test.ts，含 macOS 环境分支）

### v1.2 —— 语法与图片增强

- [x] **图片缩放 / 对齐**：点击图片出现缩放手柄，宽度按比例存入 attrs（ProseMirror image 扩展）
  - 实现提示（已实现：src/image-attrs.ts）——imageSchema.extendSchema 扩展 width/align/zoom 三属性 + ImageView 节点视图（点击图片出对齐浮层与右下角拖拽手柄）。存储格式兼容 Typora：无属性保持原生 `![]()` 语法零变化，有属性序列化为 `<img src=... width="300" align="right">`，Typora 的 `style="zoom:X%"` 原样往返不折算（折算需异步取 naturalWidth 且不可逆）。remark 阶段把 mdast 的 `<img>` html 节点转成 image 节点，序列化反向走 html 节点（remark-stringify 逐字输出）；导出管线在 html:false 下把 text 中的 `<img>` 标签还原为真实 image token 再渲染（export.ts）；粘贴白名单同步放行 width/align/zoom（paste-html.ts）。纯函数/remark 转换/schema/节点视图四段式与 mermaid.ts 同构，单测 24 例（image-attrs.test.ts）
- [x] **语法扩展**：脚注、`==高亮==`、上下标、YAML front matter（渲染为属性表，保存时原样保留）
  - 实现提示（已实现：src/mark-ext.ts + src/frontmatter.ts）——**脚注** gfm preset 只内置 schema 与 remark 解析、**不含输入规则**，mark-ext.ts 补齐三条：行内 `[^label]` 输入 `]` 即原子化为 footnote_reference；新行 `[^label]: `（尾随空格）整段转为 footnote_definition（dl/dt/dd），正则兼容原子占位符 `￼`（U+FFFC）与字面文本两种形态、整段替换避免残留空段落；定义块最后子块段尾 Enter 退出到正文段落（footnoteDefExit，Typora 同款）。另补 CSS 与导出（markdown-it-footnote + 脚注锚点样式）；**高亮/上下标**自研 `$remark` transform（只切分 mdast text 节点，行内代码/公式/链接天然免疫；`~x~` 需按 position 回溯源码纠正 remark-gfm 的 singleTilde 误判），三种语法 `^x^`/`~x~` 与 `^{x}`/`_{x}` 均解析、序列化统一 Pandoc 单符号风格，导出侧用 markdown-it-mark/sub/sup；**front matter** 经 remark-frontmatter 解析为原子块节点，NodeView 双态（键值属性表 ↔ YAML 文本编辑），value 存围栏原文字节级往返（join 规则不加空行、CRLF 保留 CR），导出 HTML/PDF 时 stripFrontMatter 剥离。输入规则带守卫：`---` 输入第三个 `-` 即刻触发且仅文档首段生效（规则先于 commonmark 注册抢在水平线规则前），行内标记规则遇未闭合反引号/$ 抑制（防公式 `$a^{b}$` 内容被提前吃掉）。快捷键：高亮 Cmd/Ctrl+Shift+H、上标 +Shift+=、下标 +Shift+-，菜单「格式」栏同步。桌面端经 CDP 自动化实测 27 项断言（输入规则/快捷键/解析往返）全过。新增单测：mark-ext 29 / frontmatter 17 / export-html 16 / format 5（其中含扩展项）
- [x] **专注模式 / 打字机模式**：设置面板开关；打字机用编辑器坐标滚动即可
  - 实现提示（已实现：src/writing-modes.ts）——专注用常驻 ProseMirror 装饰器插件给光标祖先链（depth 1..depth）挂 `.fm-active`，CSS 只变暗顶层块与列表项、祖先链整链置亮（避开 opacity 嵌套乘算），开关切换派发空事务重算、不重建编辑器；仅所见即所得生效。打字机为纯 DOM 方案（selectionchange + rAF 节流，把折叠光标滚到 .page-scroll 垂直中央，首末段停在滚动边界），所见即所得与源码模式均生效。两个独立开关（设置面板「写作模式」区），localStorage 持久化，无菜单/快捷键
- [x] **排版设置**：字体、字号、行距、编辑区宽度、自动换行开关（设置面板 + localStorage 持久化，写入 CSS 变量）
  - 实现提示（已实现：src/typography.ts + store.ts）——单键 JSON 存储（tmd:typography），注入 `--editor-*` CSS 变量（`--editor-font / -font-size / -line-height / -page-width / -overflow-x`），style.css 以 `var(--editor-*, 默认值)` 消费，不触碰编辑器实例；字体预设与自定义字体栈输入联动；字号同步作用于源码模式（CodeMirror 消费同一变量），其余仅作用于正文
- [x] **最近打开接入系统**：主菜单"打开最近"子菜单；`app.addRecentDocument` / Windows Jump List 注册
  - 实现提示（已实现：electron/main.cjs + src/files.ts）——最近列表权威仍在渲染层 localStorage（侧边栏/快速切换共用），主进程只存镜像构建「文件 → 打开最近文件」子菜单。新增 5 条 IPC：recentSync（启动全量同步建菜单，不碰系统列表）/ recentAdd（打开或保存新文件时 addRecentDocument 注册到 Windows Jump List、macOS Dock 菜单、Linux recent，并去重置顶重建菜单）/ recentClear（clearRecentDocuments 清系统记录）/ recentRemove（侧边栏 × 单条移除；Electron 无单条删除系统记录 API，主进程清空后按剩余条目从旧到新重新注册）/ recentOpen（菜单项点击回传路径，渲染层走 openPath）。侧边栏行 hover 显示 × 单条移除（filetree.ts renderRecent 可选 onRemove），菜单另有「清空最近文件」复用 IPC.menu 的 clear-recent 动作；失效路径（已移动/删除）toast 提示，记录保留（移动盘临时不可达不丢条目）。macOS Dock / Windows Jump List 点击经既有 open-file 事件 / argv 文件关联链路打开，无需额外代码。侧边栏副标题旁另设「清空」按钮（renderFilesSidebar 按列表非空显隐，window.confirm 二次确认，浏览器降级环境同样可用，弥补无原生菜单的入口缺失）
- [x] **导出跟随主题**：导出 HTML 按当前主题输出（EXPORT_CSS 参数化）；PDF 补页边距 / 页眉页脚选项
  - 实现提示（已实现：src/export.ts）——导出瞬间抓取 documentElement 计算后的主题变量快照注入导出页 `:root`（深浅模式、预设、自定义 CSS 的变量覆盖自动跟随），导出 CSS 全部 `var()` 消费带浅色兜底；mermaid 图随深浅切 dark/default 主题。PDF：新增 `@media print` 样式（隐藏工具栏/侧栏/标签栏/悬浮层，解除滚动裁剪链避免只打出可视区，`@page` 18mm 页边距，代码块与 mermaid 图防跨页断开）；页眉页脚与纸张参数走系统打印对话框
- [x] **多文件夹工作区**：侧边栏可同时挂载多个文件夹（多根并存），行内 hover × 单条移除、副标题旁一键清空

### 明确不做

- **多窗口**：多标签页已覆盖「多文件来回切」，多窗口真正不可替代的只剩跨屏并排与同一文件双视图，对轻量单文档编辑器价值有限；且成本远高于收益——渲染层虽因进程隔离天然可用，但主进程要把 30+ 个 `ipcMain.handle` 改为按 `event.sender` 定位来源窗口，并隔离恢复副本 / 脏状态 / 窗口几何，重定退出语义（详见下方决策记录）。对照场景用系统级窗口并排（Windows `Win`+方向键 / macOS 分屏）即可
- **默认窗口最大化 / 窗口几何持久化**：窗口维持固定初始尺寸（1000×800）启动，不自动最大化，也不记忆用户调整后的尺寸与位置。最大化本是用户的按需动作（双击自绘标题栏拖拽区即由系统处理最大化/还原，或 `Win`+方向键），应用代劳反而剥夺选择；持久化几何还要处理多显示器拔插、DPI 缩放变化与窗口落到屏幕外等边界，投入与收益不成比例
- **双链 `[[wiki]]` / 反向链接 / 图谱**：Obsidian 的赛道，TMD 定位是轻量文档编辑器，做了会拖垮简洁性
- **插件生态 / 第三方 marketplace**：维护成本与安全面远超项目体量
- **云同步 / 账号体系**：坚持本地优先、无账号（与开源分发原则一致）
- **移动端**：桌面壳架构不适用，投入产出比低

#### 决策记录：为什么多窗口排在同窗分屏之前，又双双不做

两者都是「并排两个文档」，但改造成本正好相反——曾评估「同一窗口左右分屏」更轻，结论是不成立：

- **同窗分屏是架构改造**：TMD 是「单例 + 换内容」架构（一个 `#editor` / `.page-scroll` / `#tab-bar`），分屏要求两个编辑器实例同时存活，必须把 `editor-core` 的 `editor`/`pmView`/`sourceMode`/`cmView`/`replaceQueue`、`tabs` 的 `activeTabId`、`find` 的查找状态、`image-resolver` 的 `baseDir`、`writing-modes` 的 `pmView` 等 10 余处单例改为按窗格索引，并新增布局（分隔条拖拽 / 宽度持久化 / 窄窗退化）与「同一文件双实例写冲突」的规则，涉及前端 15+ 文件。Obsidian 做分屏轻松是因为它从第一天就是 pane 架构
- **多窗口是机械改造**：每个窗口独立进程，上述单例天然成立，改动集中在主进程与少量持久化隔离（4-6 个文件），但面广且要重定退出语义

即「看似更轻的同窗分屏实际更重」，而两者的共同价值（双文档对照）都可用系统级窗口并排替代，故一并搁置；如未来重提，优先做多窗口的轻量形态（副窗口只托管单个文件的编辑器，无侧边栏与标签栏）。

## 4. 优先级原则

1. 先补「日常写作高频路径」的短板（表格、图片、粘贴），再做低频管理功能（搜索）
2. 每个版本保持「可发布」状态：功能列表宁少勿滥，做完即打 tag
3. 涉及数据格式（如图片 attrs、front matter）的改动，必须先确认序列化兼容：旧文档打开无损、保存后其他编辑器可读
