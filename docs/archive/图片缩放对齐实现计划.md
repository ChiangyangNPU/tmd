# 图片缩放 / 对齐（v1.2）实现计划

## Context

差距表第 2 名的图文混排短板：图片无法缩放/对齐。目标：编辑器内点击图片出拖拽缩放手柄 + 对齐浮层（左/中/右/重置），宽度持久化到 Markdown。

**已与用户确认的决策**：
- 持久化格式（Typora 同款）：无 attrs 时保持 `![alt](src "title")` 现状零变化；有 attrs 时序列化为 `<img src alt title width align>` HTML 标签兜底。兼容打开 Typora 缩放过的文档（`style="zoom:50%"`）
- 对齐三档（left/center/right）持久化
- 路线图原则：旧文档无损、其他编辑器可读（GitHub/VS Code/Obsidian/Typora 均渲染 `<img width>`）

**已核实的技术事实**：
- preset-commonmark 的 `imageSchema`：inline/atom/draggable，attrs 仅 src/alt/title；`extendSchema(handler)` = `$nodeSchema(id, handler(schema))`，同名 id 经 upsertById 覆盖（@milkdown/utils L301-316），**必须晚于 `.use(commonmark)` 注册**
- remark-parse 11 默认产出行内/flow 两种 `html` mdast 节点；remark-stringify 对 html 逐字输出（不转义）——序列化走 `addNode('html', ...)`，解析侧须在 remark 阶段把 img html 节点替换回 mdast image（否则被预设 htmlSchema 吞成文本）
- preset-commonmark 自带 htmlSchema 会把 html 节点显示为文本
- `Decoration.node` 的属性打在 NodeView 外层 dom，NodeView 须自行从 decorations 读（image-resolver 的 file:// src 需要传递到内层 img）
- 导出管线 markdown-it `html: false` 会把 `<img>` 转义为文本，需专门处理

## 实施步骤

### 1. 新建 `src/image-attrs.ts`（纯函数核心，全部可单测）

- 类型：`width: number | null`、`align: '' | 'left' | 'center' | 'right'`、`zoom: number | null`（zoom 保留给 Typora 往返，不折算 width——折算需异步 naturalWidth 且不可逆）
- `escapeHtmlAttr(s)`：`&<>"` 转义
- `serializeImgHtml(attrs)`：无 width/zoom/align 返回 null（保证现状零变化）；有则输出 `<img src="…" alt="…" title="…" width align style="zoom:X%">`（属性转义、白名单输出）
- `parseImgHtml(html)`：正则预检 `^<img\s` + 正则属性表解析（`ATTR_RE`，无 DOMParser 依赖），白名单属性 src/alt/title/width/align/style（style 仅提取 zoom 声明，`ZOOM_RE` 同时兼容 `zoom:50%` 与无单位 `zoom:0.5`——后者 ×100 归一，钳制 1..1000）；src 安全校验复用 paste-html.ts 的 `isSafeImageSrc`（L102）；width 钳制 32..99999
- `transformImgHtmlNodes(tree)`：遍历 mdast——行内 html 节点命中 → 原位替换为 `{type:'image', url, alt, title, data:{width, align, zoom}}`；flow 级（父节点在白名单 `FLOW_PARENTS = root/blockquote/listItem` 内）→ 包一层 paragraph 再替换（root 不收 inline）；TOC 注释与非 img 不动
- 导出 remark 插件 `imgAttrsRemark = $remark('imgAttrsRemark', ...)`

### 2. 同文件 schema 扩展 + NodeView

- `imageSchemaExt = imageSchema.extendSchema(prev => ctx => ({...}))`：
  - attrs 增 width(null)/align('')/zoom(null)
  - parseDOM：读 width/align/style zoom
  - toDOM：`['span.pm-image', …, ['img', {style: width/zoom, class: align}]]`
  - parseMarkdown runner：读 node.data 带入新 attrs
  - toMarkdown runner：无 attrs 走原 mdast image 路径；有 attrs 走 `state.addNode('html', undefined, undefined, serializeImgHtml(...))`
- `ImageView` NodeView（仿 [mermaid.ts](file:///Users/juran/MyFiles/Study/workspace/gitee/tmd/src/mermaid.ts) L122-243 骨架：constructor/update/ignoreMutation/stopEvent）：
  - dom：span.pm-image > img + 右下角拖拽手柄 + 顶部对齐浮层（四按钮：左/中/右/重置）
  - `selectNode/deselectNode` 切选中态显隐手柄与浮层
  - `update(node, decorations)`：同步 width/zoom/align 样式；从 decorations 读 file:// src 施加到内层 img；独占段落单图加 `--solo` 类（Typora 同款自动居中，显式 align 优先）
  - 拖拽：mousedown 记起点，mousemove 仅改 DOM 预览，mouseup 一次 `tr.setNodeMarkup`（单步撤销）；max 取 `.ProseMirror` clientWidth；拖拽产 width 并清 zoom
- 导出 `imageAttrsPlugins = [imgAttrsRemark, imageSchemaExt, imageView]`

### 3. 装配 `src/editor-core.ts`

## 风险与回退

- 扩展件必须晚于 commonmark use，否则 schema 被顶回（症状：attrs 丢失）——装配顺序是唯一硬约束
- 显式居中 display:block 会把「图文同段」视觉拆行（Typora 同款行为），PM 结构不变
- 回退点：editor-core 一行 use 摘除即整体回退
